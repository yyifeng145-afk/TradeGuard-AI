# TradePilot 业务流程对照与迭代分析

> 文件编码：UTF-8。参考来源为 [TradePilot GitHub 仓库](https://github.com/feifei9126/tradepilot) 的公开说明；这里只借鉴业务流程，不复制其源码或品牌资产。

## 1. 需求理解

目标是把 Northstar CRM 从“询价到报价交付”的可信 Agent 演示，扩展为适合外贸团队日常使用的经营闭环，同时继续保证模型不能绕过定价、审批和租户权限。

一期聚焦：客户询价 → 报价审批 → 人工交付 → 客户接受/拒绝 → 订单 → 生产/交期风险 → 出货 → 完成。

## 2. 功能拆解

| 能力 | 改造前 | 本轮结果 | 后续阶段 |
| --- | --- | --- | --- |
| 客户、询价、报价 | 已有可信 Agent 流程 | 保留 | 增加联系人、标签、客户来源和商机阶段 |
| 客户反馈 | 报价交付后流程中断 | 新增接受/拒绝及外部凭据 | 真实渠道回执自动关联 |
| 报价转订单 | 缺失 | 客户接受后生成不可变订单快照 | 多产品报价和订单行 |
| 履约跟踪 | 缺失 | 新增确认、生产、风险、待出货、出货、完成、取消 | 供应商、质检、物流节点和收款计划 |
| 交期风险 | 无结构化状态 | 风险说明强制留痕 | 逾期自动识别、待办和飞书升级提醒 |
| 出货凭据 | 缺失 | 出货必须记录物流/提单编号 | 物流 API 与送达回执 |
| 数据并发 | 无订单并发场景 | 订单更新使用版本号防覆盖 | PostgreSQL 行锁及可靠队列 |

## 3. 页面与交互

- “报价与审批”：交付完成后可登记客户接受或拒绝，必须选择渠道并填写外部回复凭据。
- “订单与履约”：显示客户、SKU、数量、金额、贸易条款、预计出货日、风险和物流凭据。
- “经营总览”：增加履约中订单、风险订单及订单金额指标。
- 所有状态更新失败时刷新最新版本，避免旧页面覆盖其他成员的操作。

## 4. API 要求

- `POST /api/quotes/:id/customer-response`：登记客户决定；接受时原子创建订单。
- `PATCH /api/orders/:id/status`：按允许的状态图更新订单，要求 `expectedVersion`。
- 两个接口均要求登录、CSRF、租户隔离和销售客户归属校验。
- 取消订单仅限经理或管理员；出货必须提交物流或提单编号。

## 5. 数据要求

- `quote_customer_responses`：保存报价、决定、渠道、外部凭据、说明和操作人。
- `sales_orders`：保存报价关键字段的订单快照，后续产品或报价数据变化不会改写历史订单。
- `order_events`：追加式保存每次状态变化及说明。
- 外部凭据按租户、渠道唯一；每份报价只能登记一个最终客户结果并生成一个订单。

## 6. 校验规则

- 未交付报价不能登记客户结果。
- 过期报价可以记录拒绝，但不能记录接受并创建订单。
- 非法状态跳转被拒绝；风险状态必须填写至少 10 字说明。
- 订单出货必须填写至少 4 字的物流/提单编号。
- 客户结果重复提交只有在决定、渠道和凭据完全一致时才按幂等请求返回。

## 7. 权限与菜单

- 销售、经理和管理员可为有权访问的客户登记结果、推进正常履约状态。
- 销售仍只能处理自己负责的客户。
- 经理和管理员可以取消尚未出货的订单。
- 财务和审计角色目前只读订单；订单付款计划尚未进入本期范围。

## 8. 测试与回归范围

- 报价接受后只能创建一份订单快照。
- 过期报价不能转订单，客户拒绝仍可留痕。
- 状态跳转、风险说明、出货凭据和取消权限校验。
- 并发版本冲突、租户隔离、客户归属、CSRF 与现有报价审批全链路回归。
- 前端 TypeScript 和生产构建检查。

## 9. 风险与待确认事项

- **Pending confirmation**：客户“接受”目前由销售依据外部消息人工登记，不等同于渠道侧已验证回执。
- **Pending confirmation**：预计出货日暂按产品标准交期的自然日计算，是否需要工作日、节假日和工厂排产日历。
- **Pending confirmation**：一期订单仅支持单 SKU；多 SKU 报价需要新增报价行与订单行模型。
- **Pending confirmation**：是否需要定金、尾款、信用账期、开票和收汇核销。
- **Pending confirmation**：是否需要供应商、质检、装箱、订舱、报关和单证模块。
- SQLite 适合单机限定负载试运行；多实例和高并发仍需迁移 PostgreSQL 与可靠消息队列。
- TradePilot 使用 AGPL-3.0；本项目仅依据公开业务描述独立实现，本轮未复制其代码。
