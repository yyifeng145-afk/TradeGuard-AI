# CRM 差异优化需求与验收说明

> 文件编码：UTF-8。

## 1. 需求理解

保留当前“询价识别—报价草稿—人工审批—交付登记—订单履约”的业务闭环，不照搬对方项目的工具数量和运行时品牌；吸收其三项能直接提高生产可信度的工程做法：统一领域权限、可校验的记忆召回、可失效的知识引用。

## 2. 功能拆分

1. REST/Agent/MCP 读取客户、产品、政策、记忆和知识时复用同一领域服务。
2. Agent 身份只能访问当前运行绑定的客户；销售 MCP 账号只能访问本人客户；所有查询必须带组织范围。
3. Mem0 最多召回 50 条候选，本地完成 Hash 去重与相关性重排，只向 Agent 注入 Top 10，并在返回前脱敏。
4. 本地确认记忆和知识文档持久化 SHA-256 内容指纹。
5. 报价引用知识时保存“文档 ID + 版本 + 内容指纹”，审批、发送或人工交付前重新校验。
6. 工具调用记录真实执行耗时，生产日志继续只保存白名单元数据。

## 3. 页面与交互

本期不新增页面。知识失效时沿用现有 `stale` 状态及运行轨迹，明确提示重新发起询价。

## 4. API 要求

- 现有 REST API 保持兼容。
- 现有 MCP 工具名称与参数保持兼容。
- MCP 与 Agent 工具内部改为调用共享领域服务，不扩大写操作面。

## 5. 数据要求

- `memories.content_hash`：规范化内容的 SHA-256。
- `knowledge_documents.content_hash`：规范化正文的 SHA-256。
- `tool_calls.duration_ms`：工具执行耗时，非负整数。
- 旧数据由启动迁移安全回填，不删除历史记录。

## 6. 校验规则

- 远端记忆必须匹配 `organizationId:customerId` 的用户作用域。
- 远端记忆与本地记忆内容 Hash 相同则不重复注入。
- 远端记忆不能成为正式报价的权威证据。
- 知识引用的状态、有效期、版本或 Hash 任一变化，报价审批/发送/交付必须失效。
- 旧格式、无法验证的知识引用按失效处理，不能静默放行。

## 7. 权限与菜单

- 不新增菜单。
- 组织隔离为所有领域查询的强制条件。
- 销售用户访问客户时强制 `owner_id` 限制；经理、财务、管理员、审计员可访问本组织客户。
- Agent 服务身份必须同时匹配组织、运行 ID 与客户 ID。

## 8. 测试与回归范围

- MCP/Agent 跨租户、销售越权、Agent 运行与客户不匹配。
- Mem0 50 条候选、Top 10、Hash 去重、脱敏、租户作用域。
- 知识版本不变但正文变化、版本变化、撤回和过期四类失效。
- 报价正常审批、生产人工交付、Worker 重试和原有 Golden Corpus 全量回归。
- TypeScript 构建与全部自动化测试通过。

## 9. 风险与待确认项

- Mem0 的实际账户数据保留策略和跨境合规材料仍需上线前由企业确认（Pending confirmation）。
- WeKnora 当前外部片段缺少可信发布版本，继续只作为 `unverified` 线索，不进入报价权威证据。
- 不引入 Pi Runtime：当前数据库队列、Lease、续租与栅栏写已经覆盖相同可靠性目标，替换运行时会增加迁移风险。
- 不为了简历凑成 18 个 MCP 工具；只有稳定、可授权、可审计的业务能力才暴露为工具。
- LLM Judge 作为后续辅助评测项，不能替代确定性权限、金额和证据规则。
